# AgentSuite policy and governance spike

**Status: experimental design and local enforcement evidence, not a production
governance feature.** Installed `kmx lift` does not enforce policy and rejects
new bundled policy rather than dropping it. The separate
`policy-spike` renderer composes the image Deployment/Service renderer from
[kaimahi-agents/kaimahi#342](https://github.com/kaimahi-agents/kaimahi/pull/342).
See the [offline object map](assets/agentsuite-governance.html).
Implementation tracking: [sajayantony/kaimahi#2](https://github.com/sajayantony/kaimahi/issues/2).
Runnable gateway examples: [MCR HTTPS allowlist and A2A denial](../agentsuite/policy/examples/agentgateway/README.md).
[All samples: concise implementation guide](../agentsuite/policy/examples/README.md).

## Decision

Keep portable **capability advertisement**, **requested restrictions**,
**operator authorization**, and **runtime enforcement evidence** separate.
An A2A skill is something an agent advertises; it is not a grant to invoke it.
A ToolProvider's network and writable-path requirements are not permission to
use those resources. An artifact's producer cannot authorize its own deployment.

Define policy semantics independently of cloud, runtime, gateway and sandbox.
At lift time, compile the effective policy into the enforcement points supported
by the destination. Reject unsupported required controls before activation.
Do not interpret observation, accepted YAML, a running Pod, or a gateway 403 as
proof that all agent activity is governed.

## Objects and boundaries

| Object | Location / status | Meaning |
|---|---|---|
| `policy.Document` | `agentsuite/policy/policy.go`, implemented | One agent's experimental requested restrictions and separate advertisement input. |
| `policy.SuitePolicy` | `agentsuite/policy/suite.go`, implemented | Suite-wide deny defaults, logical resources and per-agent requests; no Kubernetes/Cilium metadata. |
| `Suite.Policy` | Experimental optional manifest file reference | Bundled policy, JCS digest-bound and carried by packing; external policy is also supported by explicit conversion. |
| `ApplicationBinding` / `ApplicationBundle` | `internal/kmx/governance`, implemented | Separate operator deployment metadata and generated Cilium policies, gateways, cards, profiles and Kubernetes workloads. Not approval or activation. |
| `Capabilities`, `Skill` | Same package, implemented | A2A 1.0.0 skill metadata; no endpoint, credential, authenticated principal or authorization. Not a complete AgentCard. |
| `Filesystem` | Same package, implemented | Explicit `write: deny`; no writable temp/cache exceptions. |
| `Network`, `Destination` | Same package, implemented | Default deny plus exact lowercase DNS hostname, scheme and port tuples. No paths, wildcards, IP literals or implicit DNS exemption. |
| `Invocations`, `Invocation` | Same package, implemented | Default deny plus explicit peer/skill references. References are requests, not approved grants. |
| `PolicyBinding` | Proposed | Trusted authority binds suite/image/agent and requested/effective policy digests to a destination, principal and validity interval. |
| `RuntimePolicyCapabilities` | Proposed | Versioned enforcement support, scope, prerequisites and unsupported semantics, independently verified rather than caller-asserted. |
| `governance.Plan` | `internal/kmx/governance`, implemented | Canonical policy/profile digests, seccomp artifact, Landlock launcher, gateway configuration and bounded coverage. Compilation is not activation. |
| `GatewayEgressProjection` | Same package, implemented | Explicitly partial lowering of HTTPS authorities to agentgateway CONNECT/SNI routes; reports unenforced obligations and cannot be used as a whole-policy deployment Plan. |
| `GatewaySandboxProjection` | Same package, implemented | Filesystem/local-socket controls that permit TCP; explicitly requires separate network enforcement and operator-owned gateway bindings. Never a whole-policy Plan. |
| `imagelift.Plan` | Existing lift plus `RenderPolicySpike`, implemented | Exact target and image identities, workload argv, security context, profile selector and policy-bound plan digest. |
| `PolicyDecision` / `ActivationReceipt` | Proposed | Approval/denial, rule IDs, effective policy digest, compiler/runtime revisions, live resource identities and enforcement evidence. |
| Smoke receipt | Generated by `scripts/ci/policy-smoke.ps1` | Positive controls, exact errno/status denials, backend hit count, artifact identities and executed-Pod hash. Not a signed attestation. |

The policy schema is closed JSON Schema 2020-12. The existing strict AgentSuite
decoder rejects duplicate keys, wrong-case fields, unknown fields and ambiguous
JSON. Semantic validation additionally rejects duplicate skill IDs, duplicate
peer IDs, self grants and IP literals. Schema validation alone is insufficient.
Portable data lives in the top-level package; translation and deployment stay
internal. The main-based tree still keeps the shared strict decoder internal;
move it with the pending AgentSuite extraction rather than duplicate it here.

Policy is deliberately **not** a non-critical suite extension. The optional
digest-bound manifest reference is now validated and packed. Existing
build/lift paths reject bundled policy; they do not claim to enforce it.
Production enforcement still requires integration at every consuming boundary.

## Exact spike semantics

The implemented backend, `linux-python-landlock-deny-v1`, supports only the
deny-all subset. The document can represent hostname/port allowlists and
peer/skill requests, but this compiler rejects either nonempty list.
No silently weakened or partially successful plan is returned.
Invocation restrictions concern outbound peer calls, not authorization of
incoming users. The local inbound probe server is intentionally credential-free
and must not be exposed outside the disposable cluster.

A separate `-gateway-egress` projection now renders the HTTPS authority subset
into real agentgateway v1.6.0 configurations. It is deliberately not a sandbox
deployment mode and cannot be combined with deployment flags. Its output reports
filesystem, bypass, identity/A2A and HTTP-inspection controls as unenforced.
Nonempty peer/skill grants are rejected; no authorization is inferred from an
SNI route. The full sandbox compiler still rejects network allowlists.

The MCR sample allows only `https://mcr.microsoft.com:443` through a CONNECT
proxy with a fixed backend. It does not terminate TLS, so all paths are allowed
and it cannot inspect HTTP methods, JWT claims or A2A operations. Cleartext
`curl mcr.microsoft.com` is intentionally rejected; the example uses
`curl.exe --proxy http://127.0.0.1:18080 https://mcr.microsoft.com/v2/`.
See the sample's expressiveness table for the remaining policy-language work.

Filesystem denial covers filesystem write opens, creation, removal, truncation
and metadata mutations. Read-only root mounts are combined with a Linux
Landlock ABI >= 3 launcher and a supplemental seccomp profile. No writable
`emptyDir` at `/tmp` survives the lift translation. The launcher restricts itself
before replacing itself with the agent; descendants inherit the restrictions.
The image must supply Python 3 and libc on Linux amd64. Missing Landlock support
is a startup error, never an unconfined fallback.

Network denial covers agent-initiated connections and explicitly addressed
datagrams, including model, tool, A2A, DNS, IPv6 and Unix-socket paths. There is
no exception for model credentials, callbacks, notifications or discovery.
An agent requiring an external model therefore cannot answer model-backed
requests under this policy. The smoke uses a deterministic server, not an LLM.

Accepted inbound socket replies and inherited stdout/stderr remain usable.
This is not a promise that no byte can leave the process: replies, logs, pipes,
anonymous memory and kernel side channels are outside the filesystem/new-call
restriction. Define data-loss prevention separately if that is required.
`sendto` with a non-null destination is denied; null-destination replies are
permitted, and `connect` remains denied. `sendmsg`, `sendmmsg`, `socketcall` and
`io_uring` paths are denied rather than assumed covered.

The dedicated agentgateway listener compiles to `require: "false"`, not an empty
allow list (which would allow traffic). Its positive-control sibling uses the
same fixed backend and `require: "true"`. The gateway and kernel tests are
complementary, not a claim that the agent uses an unavoidable gateway:
under deny-all the agent cannot even initiate a connection to that gateway.

## Trust and enforcement gaps

The Kubernetes administrator, node and runtime are trusted. An administrator
installs the content-addressed seccomp profile and labels the eligible node.
The rendered workload selects that label and names that exact profile. A missing
profile prevents container startup. A label alone is not cryptographic evidence
of profile contents; continuous verification and admission are follow-ups.

Landlock follows a process tree, not every process in a container. Kubernetes
`exec`, debug/ephemeral containers, unconfined sibling containers, privileged
workloads and node-level access need independent RBAC/admission restrictions.
The smoke intentionally invokes tests through the governed server so they
descend from the launcher; it does not use `kubectl exec` into the governed Pod
and misrepresent that process as Landlock-confined.

The supplemental default-allow seccomp profile is not a general sandbox
certification. Future kernels, architectures, device ioctls, file descriptors
inherited from a different harness and runtime upgrades need dedicated
conformance work. Neither gVisor nor Azure sandbox enforcement was run.
No native Orka or kagent agent was installed or registered.

## Reproduce on kind with Podman

Prerequisites: PowerShell 7, Podman, a dedicated running kind cluster, Go 1.26+
and kubectl. This spike used rootful Podman inside its own WSL machine because
Windows-host kind with rootless Podman failed the systemd `Delegate=yes` check.
The existing kubeconfig/context was not changed.

The tools directory used by the script contains `go\bin\go.exe`, `kubectl.exe`
and a dedicated `policy-kubeconfig`. Create the cluster with:

```powershell
podman machine init kaimahi-policy-spike
podman machine set --rootful kaimahi-policy-spike
podman machine start kaimahi-policy-spike
$env:KIND_EXPERIMENTAL_PROVIDER = 'podman'
kind create cluster --name kaimahi-policy-spike --kubeconfig "$Tools\policy-kubeconfig" --wait 180s
.\scripts\ci\policy-smoke.ps1 -Tools $Tools -OutputDirectory "$Evidence\policy-run"
```

Use a new output directory and namespace per run. The script refuses to reuse
an existing namespace. It pulls digest-pinned Python and agentgateway images
through the node's CRI, installs only the named profile, renders the plan,
starts a credential-free control workload and the governed workload, and writes
`plan.json`, `seccomp.json`, `executed-pod.json` and `receipt.json`.
It never uses external model credentials.

The executed PodSpec is the renderer's PodSpec, including the launcher and
explicit test command. Source suite/composition identities are synthetic.
This is a real kernel/gateway test of the PR's **renderer integration**, not
a registry-backed image build/lift or an A2A protocol interoperability test.

Resources are retained for inspection. Remove only the receipt's dedicated
namespace when finished, using the explicit kubeconfig/context. Leave the
named kind cluster and its profile installed for subsequent spike work.
Failed initial-run namespaces can be removed independently.

## CPU-backed agent example

The [sample guide](../agentsuite/policy/examples/README.md) describes the layers.
This uses a **second** kind cluster with Cilium, leaving the kindnet deny-all
cluster unchanged. Agentgateway is independent of Cilium; Istio is not used.
Prerequisites: the existing Podman/tools setup plus Helm on PATH (validated with
Helm 4.3.0). From the worktree, in PowerShell 7:

```powershell
$env:KIND_EXPERIMENTAL_PROVIDER = 'podman'
& "$Tools\kind.exe" create cluster --name kaimahi-cpu-agents --config .\agentsuite\policy\examples\kind-cpu-agents\kind.yaml --kubeconfig "$Tools\cpu-agents-kubeconfig"
helm install cilium oci://quay.io/cilium/charts/cilium --version 1.20.2 -n kube-system --kubeconfig "$Tools\cpu-agents-kubeconfig" --set ipam.mode=kubernetes --set kubeProxyReplacement=false --set operator.replicas=1 --wait
.\scripts\ci\policy-cpu-smoke.ps1 -Tools $Tools -OutputDirectory .\evidence-cpu
```

The runner accepts only its two documented policies/topology. Unknown requests
fail before namespace creation. It validates native configs, installs hashed
filesystem profiles, creates default-deny network policies, downloads the model,
removes bootstrap egress, and starts the agents. Inference and single-skill
endpoint bindings are deployment-owned restrictions, not newly standardized
portable HTTP or A2A authorization types. Trusted labels, kubelet, administrators
and the validator remain outside the agent boundary.

For an interactive request, set `$Namespace` from the receipt and run:

```powershell
& "$Tools\kubectl.exe" --kubeconfig "$Tools\cpu-agents-kubeconfig" -n $Namespace port-forward pod/coordinator 18081:8080
# Another terminal; the port-forward is trusted operator access:
curl.exe --noproxy "*" http://127.0.0.1:18081/skills/coordinate/message:send -H "Content-Type: application/json" --data-binary "@.\agentsuite\policy\examples\kind-cpu-agents\request.json"
```

`scripts/test_policy_cpu_agent.py` checks envelope validation and failure
propagation offline (`python3 -B scripts/test_policy_cpu_agent.py`). Only the
cluster smoke proves enforcement. It records live pod/image identities, policy
digests, the model digest/CPU placement, generated objects and actual results.
The model tag is resolved at download time and recorded; it is not an immutable
model-version lock. Model caches disappear with their containers.

## Suite policy to application

The [full sample](../agentsuite/policy/examples/suite-application/README.md) adds
two complete suites: one bundles policy, the other receives it separately.
Both use the same portable intent. A separate binding pins the suite/policy
digests and maps logical identities to images, namespace, workloads and model.
Conflicting bundled/external policies fail rather than silently overriding.

The converter emits native CiliumNetworkPolicy through `cilium.go`, gateway
routes/workloads through `application_runtime.go`, cards through `a2a.go`,
and filesystem profiles through the shared sandbox projection. The shared
agent runtime is embedded from `internal/kmx/governance/cpu_agent.py`.
It consumes suite instructions and uses the bound logical model through the
OpenAI-compatible API; `reasoning_effort: none` avoids empty final answers from
the small CPU model. Empty/incomplete answers fail the sample.

The activation runner creates policies/services first, verifies profiles,
downloads model weights under a temporary bootstrap policy, removes that policy,
then starts agent workloads. Services must exist before agents because service
IP environment injection avoids granting agents DNS access. The trusted validator
has explicit broad egress for positive controls; it is not a governed agent.

Both modes passed real two-agent inference and all 23 probe groups on Cilium
kind, with MCR HTTP 200 and zero model VRAM. This is a bounded converter, not
arbitrary AgentSuite image construction or production `kmx lift` integration.
General protocol authorization and governance approval remain separate work.

## Component plan / implementation checklist

These are follow-ups, not capabilities implied by the spike.

- [ ] **Spec and identity:** finalize independent capability/request/authorization objects; add mandatory digest-bound policy references to the suite/agent graph, schemas, canonical identities, OCI packing and offline validation. Reconcile the top-level AgentSuite extraction without duplicating validators.
- [ ] **Protocol policy types:** define typed HTTP path/method matching, caller conditions and separate A2A/MCP/model actions, with explicit inspection requirements and unsupported-control negotiation. Keep native CEL/configuration and environment credentials out of the portable policy.
- [ ] **Policy composition:** define intersection of author requests, organization ceilings and environment grants. Absence must not mean allow. Reject contradictory ToolProvider writable-path/network requirements; bind invocation edges and model requirements to effective permissions.
- [ ] **Governance authority:** add target/principal-bound PolicyBinding, approval and validity semantics, revocation, audit events and receipts through existing lifecycle ports. Do not resurrect the retired custom governance plane or put grants into the model-metering service.
- [ ] **Whole-suite lift:** extend DeploymentSuite snapshots, BuildPlan/image binding, SuiteDeployRequest, member bindings, prepare/inspect/deploy and receipts. Prepare every member and every enforcement resource before writes; include policy/compiler/native-object digests in review identity; preserve partial-outcome and ownership rules.
- [ ] **Activation ordering:** install and verify policies before starting agents; activate routes only after sandbox readiness; on update drain/revoke existing connections as specified. Recheck profile, gateway and policy fingerprints after approval, and report drift.
- [ ] **Gateway translation:** bind authenticated workload identity to a fixed upstream; prevent Host/SNI spoofing, redirects, proxy bypass, direct IP access and DNS rebinding. Separate model, MCP, A2A and arbitrary HTTP authorization. Preserve streaming/cancellation while rejecting unauthorized skill operations.
- [x] **Gateway sample/projection:** map exact HTTPS host/port requests into pinned CONNECT/SNI configuration with fixed backends; show MCR success and unlisted-host/port/cleartext denial. Explicitly report remaining whole-policy obligations.
- [x] **CPU integration sample:** run two model-backed agents with dedicated gateways, Cilium bypass prevention and filesystem restrictions; document fixed skill endpoint bindings without claiming general A2A authorization.
- [x] **Suite application spike:** bundled/external digest-bound policy, separate deployment bindings, independent Cilium/gateway/card projections, packing round-trip and both delivery modes exercised on kind. Unsupported legacy build/lift paths reject bundled policy.
- [ ] **Hostname/port allowlists:** choose an enforceable transport path (policy-capable CNI plus authenticated gateway or equivalent sandbox proxy). kind's default kindnet is not evidence of NetworkPolicy enforcement. Add allowed-host success, denied-host failure, wrong-port failure and bypass probes.
- [ ] **A2A adapter:** project advertisement into the runtime's version-pinned AgentCard; bind endpoint/authentication at deployment. Keep caller principal, peer identity and skill grants separate; cover discovery, message sends, task operations, streaming and push callbacks.
- [ ] **Orka adapter:** map only documented tool/delegation controls, validate actual runtime enforcement, and preserve immutable runtime revisions. Current pinned CRD fixtures are evidence of fields, not proof of OS egress or filesystem isolation.
- [ ] **kagent adapter:** validate `sandbox.network.allowedDomains`, supported sandboxed execution paths and A2A `allowedNamespaces` semantics against actual controllers. Do not broaden exact host/port tuples into wildcard/domain-only grants.
- [ ] **Azure sandbox adapter:** map default deny and inspection mode together; `Partial` can permit non-HTTP traffic whereas `Full` blocks it. Validate filesystem controls separately; do not infer them from network policy.
- [ ] **gVisor and observability:** evaluate runsc as an isolation backend and enforce explicit network/filesystem policy separately. Use Inspektor Gadget for correlated observations; observation alone must never satisfy a required preventive control.
- [ ] **Conformance and operations:** test unsupported/missing controls, privilege/debug/exec bypass, injected sidecars, profile tampering, restart/update/revocation, multi-architecture behavior and signed evidence. Add CI with an explicitly configured local backend; no skipped enforcement test should count as a pass.

## Primary references and discovery limits

- [A2A specification](https://a2a-protocol.org/v1.0.0/specification): AgentCard capabilities, security requirements and protocol operations are distinct.
- [kagent v0.10.2 Agent types](https://github.com/kagent-dev/kagent/blob/v0.10.2/go/api/v1alpha2/agent_types.go): `SandboxConfig`, `NetworkConfig`, `AllowedNamespaces`, A2A advertisement and BYO protocol contract.
- Orka v0.2.0 vendored CRDs: `internal/kmx/orkaschema/fixtures/v0.2.0/agents.yaml` and `tasks.yaml`; upstream API discovery was blocked by organization SAML authorization. No attempt was made to work around it.
- [agentgateway authorization](https://agentgateway.dev/docs/standalone/latest/documentation/configuration/security/http-authz/): empty rules allow; `require` fails closed on evaluation errors.
- [Cilium on kind](https://docs.cilium.io/en/stable/installation/kind/): disable default CNI and install a policy-enforcing network implementation.
- [Qwen3 CPU-sized model](https://ollama.com/library/qwen3:0.6b): local inference; the small model's prose quality is not the policy test oracle.
- [Azure sandbox egress policy](https://learn.microsoft.com/en-us/azure/container-apps/sandboxes-egress-policies): ordered rules, defaults, inspection modes and in-flight update limitations.
- [gVisor architecture](https://gvisor.dev/docs/): application-kernel isolation is not a portable policy language.
- [Inspektor Gadget](https://inspektor-gadget.io/docs/latest/): eBPF collection/inspection and enrichment, not automatic enforcement.
- [Landlock userspace API](https://docs.kernel.org/userspace-api/landlock.html): inherited process restrictions and ABI-dependent filesystem controls.
- [kind rootless guidance](https://kind.sigs.k8s.io/docs/user/rootless/): provider and cgroup delegation requirements.
