AgentSuite: policy is not capability

Experimental spike. Provider-neutral intent, target-specific translation, and real local deny-all probes. Not production governance, full A2A conformance, or a certified sandbox. Component plan, evidence and limitations.

Tracking: sajayantony/kaimahi#2.

Runnable MCR allowlist and native A2A gateway samples.

Object flow and trust boundaries

1. Author intent

policy.Document

Agent identity, A2A advertisement, filesystem, network and invocation requests.

Author cannot grant authority.

2. Operator authority

PolicyBinding

Proposed: intersect requested policy with organization ceilings and approved destination/principal grants. Bind exact digests and validity.

3. Compile at lift

governance.Plan

Exact policy/profile identities, launcher, native controls and bounded coverage. Unsupported required controls return an error, not a weaker plan.

4. Runtime execution

imagelift.Plan

Policy-bound PodSpec; read-only root, no writable temp volume, Landlock launcher, seccomp profile and eligible-node selector.

5. Governance evidence

ActivationReceipt

Proposed: approval, live resource identities, compiler/runtime revision, enforcement probes, drift and revocation. A JSON plan is not an attestation.

Enforcement is layered

LayerLocal implementationEvidence / limit
FilesystemRead-only root + Landlock ABI >= 3 + mutation syscall denialRoot/temp writes fail with EROFS; shared-memory/device write opens with EACCES; mutation calls with EPERM.
New outbound callsseccomp denies connect and explicitly addressed datagramsDirect model/tool/A2A, IPv6, UDP, DNS datagrams, Unix sockets and child calls denied. Inbound replies remain possible.
Gatewayagentgateway require: falseFour HTTP paths return 403; positive route returns 200; denied requests add zero backend hits.
Hostname/skill allowlistsGateway HTTPS authority projection implemented; full sandbox and skill grants pendingMCR returns 200 through CONNECT; unlisted SNI, forged Host, wrong port and HTTP are rejected. The full sandbox compiler still fails closed on allowlists.
Native runtimesOrka / kagent / Azure / gVisor: future adaptersNo equivalence or deployment claim. Inspektor Gadget is an observation source, not enforcement proof.

URL allow example: Microsoft Container Registry

"network": {
  "default": "deny",
  "allow": [{"scheme": "https", "host": "mcr.microsoft.com", "port": 443}]
}

curl.exe --noproxy "" --proxy http://127.0.0.1:18080 https://mcr.microsoft.com/v2/

GatewayEgressProjection emits CONNECT/SNI routes with a fixed mcr.microsoft.com:443 backend and an explicit list of unenforced controls. TLS passthrough cannot inspect URL paths, methods, caller claims or A2A skill operations. A bare curl without the proxy is not governed.

Process-tree boundary: Landlock inheritance does not automatically cover Kubernetes exec/debug tasks or unrelated sidecars. Admission, RBAC, trusted launchers and node/profile verification remain required before production use.
