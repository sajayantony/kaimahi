A local Kaimahi agent, running as a durable session inside Substrate

This document walks through the new Kaimahi → AgentSessions → Substrate path: what changed, how execution crosses each boundary, and what happened when the POC ran end to end on a Podman kind cluster with a local Ollama thinking model.

What exists now

Kaimahi can take a portable agent authored locally, send its exact identity and behavior to AgentSessions, and receive an answer while AgentSessions places the chat harness in a real Substrate Actor.

Kaimahi
1 command

Selects the AgentSessions runtime, reads the local bundle, and prints answer-only output.

AgentSessions
Durable turn

Records system and user messages, portable digest, model identity, and the completion.

Substrate
1 Actor

Runs the harness in an isolated Actor while model networking remains host-side.

The important boundary: the Actor never receives Ollama credentials. It asks the AgentSessions host to perform the model call over Harness.Connect. Replay later consumes the recorded model result without contacting Ollama.

The architecture at a glance

The portable agent stays runtime-neutral. Kaimahi is the producer, AgentSessions owns durable session evidence, and Substrate owns the sandboxed compute incarnation.

The experience, step by step

The POC deliberately reuses Kaimahi’s existing portable bundle instead of inventing a second “AgentSessions agent” format.

Create a local portable agent

Use Kaimahi’s normal offline Orka authoring path. The resulting agent.yaml is portable; an empty Orka extension is acceptable because no Orka-only behavior needs to be discarded. 

kmx agent create local-reviewer \
  --runtime orka \
  --model qwen3:8b \
  --instructions ./reviewer-instructions.txt \
  --provider-type openai \
  --base-url http://ollama.ollama.svc:11434/v1 \
  --secret local-model \
  --bundle-path ./agents/local-reviewer \
  --no-apply

Install the Substrate-side harness and host

Build the harnessnode and agentsessions-substrate images, replace the manifest placeholders, then apply the chat ActorTemplate followed by the host Deployment. On the Apple Silicon kind node, both images must be built explicitly for linux/arm64. 

export KO_DEFAULTPLATFORMS=linux/arm64

# Build and substitute MODEL_ID, MODEL_BASE_URL, HOST_IMAGE and harness image.
kubectl apply -f deploy/substrate/chat-actortemplate.yaml
kubectl apply -f deploy/substrate/kaimahi-host.yaml

kubectl -n ate-agentsessions rollout status \
  deployment/kaimahi-agentsessions
Two live-cluster findings: ActorTemplate specs are immutable, so changing an image requires deleting and recreating the template. The host also needs the additive NetworkPolicy in kaimahi-host.yaml because this path uses direct PodIP h2c gRPC to WorkerPool pods.

Keep the API private and port-forward it

The POC Service is intentionally ClusterIP. AgentSessions currently has no authentication, authorization, or transport security, so do not expose it to an untrusted network. 

kubectl -n ate-agentsessions port-forward \
  service/kaimahi-agentsessions 18080:8080

Run the local agent through AgentSessions

Kaimahi reads the bundle, verifies that AgentSessions can honor it, sends a strict JSON turn to agentctl over stdin, and leaves stdout clean for the answer. 

kmx agent run ./agents/local-reviewer \
  --runtime agentsessions \
  --server 127.0.0.1:18080 \
  --project substrate-poc \
  --prompt "Review this design for concurrency risks."
What you see: the session UID is written to stderr for recovery; stdout contains only the agent’s final answer.

Inspect or replay the durable session

Use the UID printed by the run. Replay re-delivers committed records and must not make another Ollama call. 

agentctl get \
  --server 127.0.0.1:18080 \
  --project substrate-poc \
  --session <session-uid>

agentctl replay \
  --server 127.0.0.1:18080 \
  --project substrate-poc \
  --session <session-uid>

What happens during the command

This is the actual control flow rather than a conceptual simplification.

1 · Parse Kaimahi strictly parses agent.yaml and computes the digest over its exact authored bytes.
2 · Gate Tools, skills, rate limits, coordination, and Kagent-specific behavior are refused because the POC cannot honor them yet.
3 · Encode Kaimahi creates a turn with name, model, digest annotations, a system instruction, and the user prompt.
4 · Create session agentctl creates a named chat session carrying model and portable identity metadata.
5 · Place Actor The AgentSessions Substrate backend asks Control to create/resume an Actor from chat-harness.
6 · Run harness The Actor’s chat harness receives typed messages and calls EventSink.Model.
7 · Call Ollama The host journals MODEL_CALL, invokes the OpenAI-compatible endpoint, and records reasoning/output/usage.
8 · Return answer The finalized output travels back through the Sessions stream; Kaimahi writes the answer to stdout.

Using an Ollama thinking model

A model such as Qwen 3 can now return its visible answer and its reasoning through Ollama’s OpenAI-compatible response shape.

Recorded

Reasoning is durable evidence

AgentSessions accepts Ollama’s reasoning field as an opaque reasoning part. The final answer remains ordinary assistant text; reasoning is recorded separately for replay continuity.

Not yet controlled

No portable reasoning-effort setting

The POC selects the model but does not yet map a Kaimahi setting to reasoning_effort or another Ollama-specific control. That should be a typed, tested extension rather than an unvalidated free-form parameter.

Discovered by E2E

Architecture-sensitive deployment details

An initial linux/amd64 image failed under the arm64 gVisor node with a generic runsc error. Rebuilding with KO_DEFAULTPLATFORMS=linux/arm64 produced a healthy Actor.

Discovered by replay

Turn-file message integrity

The first run exposed an extra empty user event because agentctl unconditionally appended its convenience input. The fix only appends a string input when it is non-empty, with a regression test covering the exact two-message turn.

Still intentionally outside this milestone: no commits or pushes have been made, and Agent Suite cross-agent delegation is separate from this single-agent POC.
